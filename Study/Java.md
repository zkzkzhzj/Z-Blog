2. 코드의 관리를 용이하게 하자
3. 신뢰성이 높은 프로그래밍을 하자

클래스, 인스턴스, 객체

인스턴스 변수, 클래스 변수, 지역 변수

메서드(소속)와 함수(단일)

JVM -> 이건 좀 제대로 보자

Method Area
 - 클래스를 읽어 정보를 저장하는 공간, 클래스 변수도 함께 생성

Call Stack
 - 메서드 작업에 필요한 메모리 공간 제공, 호출 스택에 쌓이며 작업 완료시 반환

Heap

매개 변수 -> 기본형은 복사, 참조형은 주소
 - 기본형 전달 시 원본 값은 보존(메서드 내부에서 변경해도 복사 값 변경)

재귀 호출

클래스 메서드와 인스턴스 메서드

인스턴스 -> 클래스 자유(반대 불가, 존재 확신X)

오버로딩(같은이름), 오버라이딩(덮어씌기)

생성자
 - 기본 생성자
 - 매개변수가 있는 생성자
 - 다른 생성자 호출 -> this, this()
 - 인스턴스 복사 생성자도 가능

**2026-03-18**

변수의 초기화
 - 인스턴스 변수는 초기화를 하지 않아도 자동적으로 기본값으로 초기화
 - 지역변수는 안됨
 - 선언과 동시에 초기화 : 명시적 초기화
 - 초기화 블럭(initialization block)
   - 클래스 초기화 블럭 -> static { }
   - 인스턴스 초기화 블럭 -> { } -> 생성자보다 먼저 수행

초기화 시점
 - 클래스 변수 -> 클래스 첫 로딩 한번 초기화 - 기본값 -> 명시적초기화 -> 클래스 초기화 블럭
 - 인스턴스 변수 -> 인스턴스가 생성될 때마다 각 인스턴스별 초기화 - 기본값 -> 명시적초기화 -> 인스턴스 초기화 블럭 -> 생성자

상속
 -> 클래스 재사용하여 새로운 클래스 작성
 -> 상위 클래스가 되는 부모 클래스에 추가되는 것은 자식 클래스에도 동일하게 추가됨 -> 반대의 경우는 모름
 -> 상속을 받는 다는 것은 부모의 확장과 비슷한 개념 -> extends
 -> 단, 생성자와 초기화블럭은 상속 X, 멤버만

포함 관계
 -> 동일한 멤버를 가진 다른 클래스 객체를 내부에 new Class 해서 포함시키는 관계

상속과 포함 관계는 비슷해보이지 않나?
 - 동일한 관계라면 상속, 가지고있는 관계라면 포함
 - 원은 점이다, 원은 점을 가지고 있다 -> 가지고 있다
 - 스포츠카는 차다, 스포츠카는 차를 가지고 있다 -> 이다

상속은 단일
 - 동일한 이름을 가진 메소드의 부모가 여려명이면? 쉬운 문제가 아니다
 - 관계의 명확함도 생김

Object 클래스 -> 최상위
